# 13 - 杀软针对性对抗（全品牌覆盖）

> 覆盖：360核晶 | 火绒6.0 | Windows Defender | 卡巴斯基 | ESET | Bitdefender | McAfee | Avast/AVG | 腾讯管家 | CrowdStrike | SentinelOne | Palo Alto Cortex
>
> 原则：每个杀软都有特定盲区，针对性绕过比通用免杀效果好10倍以上

---

## 一、360核晶（QVM 7.x）

### 检测架构
```
QVM 7.2 核心：深度Hook NtProtectVirtualMemory
→ 内嵌x86/x64指令解码器
→ 语义等价性验证
→ CPCD（跨进程调用链重构）Hook
→ 主动防御 + 长城云查杀
```

### 绕过方式

| 方式 | 原理 | 效果 |
|------|------|------|
| **间接Syscall** | 绕过用户态NtProtectVirtualMemory Hook | ⭐⭐⭐⭐ |
| **分阶段内存RW→RX** | 不直接申请RWX，语义分析无法关联 | ⭐⭐⭐⭐ |
| **Go + garble编译** | 静态特征库缺乏Go样本 | ⭐⭐⭐⭐ |
| **延迟执行 >3分钟** | 绕过沙箱超时窗口 | ⭐⭐⭐ |
| **合法进程注入** | svchost作为宿主，360不杀系统进程 | ⭐⭐⭐⭐⭐ |
| **数字签名窃取** | 降低主动防御触发阈值 | ⭐⭐⭐ |
| **回调执行** | 不用CreateThread，避开线程创建监控 | ⭐⭐⭐⭐ |

### 360盲区
- **Go编译的程序**：静态特征库中Go样本较少
- **回调型执行**：CreateTimerQueueTimer、EnumFonts等不受监控
- **进程镂空后的合法进程**：不对系统关键进程进行深层行为扫描
- **MSSQL xp_cmdshell**：360会拦截（和火绒不同）

## 二、火绒 6.0（Huorong）

### 检测架构
```
火绒 BEP 4.1：
→ 放弃内核API Hook，改用ETW订阅（Microsoft-Windows-Kernel-Process/Thread Provider）
→ sysdiag.sys 内核驱动（保护HipsDaemon/HipsMain/HipsTray）
→ 命令行正则匹配检测
→ 勒索诱捕蜜罐文件
→ 6.0新增内存查杀
```

### 绕过方式

| 方式 | 原理 | 效果 |
|------|------|------|
| **OLLVM混淆** | 火绒对OLLVM混淆的静态检测极弱，通过率100% | ⭐⭐⭐⭐⭐ |
| **命令行字符串混淆** | 火绒用正则匹配拦截（非证书校验），可被混淆绕过 | ⭐⭐⭐⭐⭐ |
| **certutil改名+引号分割** | `copy certutil.exe c.exe && c.exe -url""""ca""""che ...` | ⭐⭐⭐⭐⭐ |
| **ETW事件伪造** | 火绒BEP依赖ETW日志，攻击者可伪造ETW Provider事件 | ⭐⭐⭐⭐ |
| **PoolParty BOF注入** | 基于线程池的变体进程注入，火绒6.0仍可绕过 | ⭐⭐⭐⭐ |
| **Sleep(300ms)绕过沙箱** | 火绒沙箱超时3秒，不监听NtResumeThread | ⭐⭐⭐⭐ |
| **驱动级终止HipsDaemon** | 利用DB5Upgrade.exe注入漏洞或驱动直接终止核心进程 | ⭐⭐⭐⭐⭐ |
| **MSSQL xp_cmdshell** | 火绒不拦截SQL Server的xp_cmdshell（360会拦截） | ⭐⭐⭐⭐⭐ |
| **DLL侧加载** | 利用带火绒信任签名的程序做DLL劫持 | ⭐⭐⭐⭐ |

### 火绒盲区
- **OLLVM/控制流平坦化**：静态检测极弱
- **正则匹配而非证书校验**：命令行可被无限混淆
- **ETW依赖**：可被伪造
- **内核驱动保护不足**：核心进程可被终止
- **无证书/哈希校验**：和360形成鲜明对比

## 三、Windows Defender（Microsoft Defender）

### 检测架构
```
→ AMSI (Anti-Malware Scan Interface)
→ ETW (Event Tracing for Windows)
→ 内存扫描（RWX区域检查）
→ 行为监控（CreateRemoteThread等）
→ Cloud-delivered protection (MAPS)
→ Network Protection
→ Attack Surface Reduction (ASR) Rules
```

### 绕过方式

| 方式 | 原理 | 效果 |
|------|------|------|
| **AMSI Patch** | AmsiScanBuffer写入ret | ⭐⭐⭐⭐ |
| **ETW Patch** | EtwEventWrite写入ret | ⭐⭐⭐⭐ |
| **间接Syscall** | 绕过ntdll用户态Hook | ⭐⭐⭐⭐⭐ |
| **分阶段内存RW→RX** | 避免RWX被内存扫描标记 | ⭐⭐⭐⭐ |
| **回调执行代替CreateThread** | CallWindowProc/纤程/APC | ⭐⭐⭐⭐ |
| **模块践踏（Module Stomping）** | 覆盖合法DLL的.text段 | ⭐⭐⭐ |
| **父进程欺骗（PPID Spoofing）** | 混淆进程树 | ⭐⭐⭐ |
| **禁用Defender（提权后）** | Set-MpPreference -DisableRealtimeMonitoring $true | ⭐⭐⭐⭐⭐ |
| **排除项添加** | Add-MpPreference -ExclusionPath "C:\" | ⭐⭐⭐⭐⭐ |
| **NullGate扫描对抗** | Defender在NtCreateThreadEx后扫描30KB → 时序绕过 | ⭐⭐⭐⭐ |

### Defender盲区
- **提权后可直接禁用**：最大的弱点
- **NtCreateThreadEx后扫描时间窗口**：30KB立即扫描，但可绕过
- **对Go/garble编译样本**：静态检测率较低
- **网络保护依赖SmartScreen**：HTTPS + 合法证书可绕过

## 四、卡巴斯基（Kaspersky）

### 检测架构
```
→ 强静态启发（机器学习PE分析）
→ 内核级行为监控（klif.sys驱动）
→ System Watcher（系统行为回滚）
→ Application Control（应用控制）
→ 网络流量SSL/TLS拦截（信任根证书注入）
→ 云KSN（Kaspersky Security Network）
```

### 绕过方式

| 方式 | 原理 | 效果 |
|------|------|------|
| **代码虚拟化（VMProtect/Themida）** | 卡巴强于静态检测，虚拟化可打破特征 | ⭐⭐⭐⭐ |
| **多级加密+动态解密** | AES→RC4→XOR链式解密，每级不同key | ⭐⭐⭐⭐ |
| **纯内存操作** | 不落盘，避免文件监控 | ⭐⭐⭐⭐ |
| **合法签名程序+注入** | 白加黑绕过Application Control | ⭐⭐⭐⭐ |
| **延迟较长（>5分钟）** | 绕过System Watcher行为分析窗口 | ⭐⭐⭐ |
| **禁止SSL拦截** | 客户端禁用卡巴证书 | ⭐⭐⭐ |
| **DLL代理加载** | 利用卡巴信任的签名程序 | ⭐⭐⭐⭐ |

### 卡巴斯基盲区
- **System Watcher回滚窗口有限**：长延迟可绕过行为关联
- **高熵值加密payload**：静态ML引擎对高熵数据的分类能力有限
- **内核驱动对抗复杂**：但用户态绕过相对容易
- **对Rust/Go罕见样本**：训练集以C/C++为主

## 十一、SentinelOne

### 检测架构
```
→ Static AI引擎（分析PE静态特征）
→ Storyline（行为关联引擎）
→ Deep Visibility（深度可见性）
→ 内核级Agent（已移除用户态Hook）
→ 云分析
```

### 绕过方式

| 方式 | 原理 | 效果 |
|------|------|------|
| **多态/每次不同编译** | S1 Static AI对每次不同的二进制较低检测 | ⭐⭐⭐⭐⭐ |
| **garble/Go编译** | 非标准PE结构，Static AI训练集不足 | ⭐⭐⭐⭐ |
| **中断行为链（Storyline）** | 用多个独立进程分段操作 | ⭐⭐⭐ |
| **LOLBins链式执行** | MSBuild→csc→rundll32 链式调用 | ⭐⭐⭐⭐ |
| **合法签名程序+注入** | S1对签名程序的Static AI评分低 | ⭐⭐⭐⭐ |
| **内存操作分阶段** | 不在同一时间窗口完成所有操作 | ⭐⭐⭐⭐ |
| **ETW阻断** | 阻止S1收集Deep Visibility事件 | ⭐⭐⭐⭐ |

### SentinelOne盲区
- **Static AI对新/罕见编译器产物**：训练数据偏差
- **Storyline引擎**：若操作分散在不同进程和时间窗口，关联断裂
- **已移除用户态Hook**：反而使syscall级攻击不易被感知（无Hook = 无事件 = 盲区）
- 2024关键：**每次重新编译的二进制Static AI评分低**
- 2025新增检测：增强了对反射型DLL加载的检测 → 使用B**外壳** = 多态 + 每次不同编译
- **PoolParty线程池注入** 绕过Storyline行为关联
- **Cronos Sleep混淆** 绕过Deep Visibility时间窗口

## 十三、总结对比矩阵

| 杀软 | 静态检测 | 动态/行为 | Hook策略 | 最大弱点 | 推荐对抗等级 |
|------|---------|---------|---------|---------|------------|
| **360核晶** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 深度内核Hook | Go编译+进程镂空 | Lv5-Lv6 |
| **火绒6.0** | ⭐⭐ | ⭐⭐⭐ | ETW订阅（无Hook） | OLLVM+命令行混淆 | Lv3-Lv4 |
| **Defender** | ⭐⭐⭐ | ⭐⭐⭐⭐ | AMSI+ETW+用户态Hook | 提权禁用+间接syscall | Lv4-Lv5 |
| **卡巴斯基** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 内核驱动(klif.sys) | 代码虚拟化+多层加密 | Lv6 |
| **ESET** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | 用户态HIPS Hook | 间接syscall+Go编译 | Lv4-Lv5 |
| **Bitdefender** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | 用户态Hook | PE头混淆+间接syscall | Lv4-Lv5 |
| **McAfee** | ⭐⭐⭐⭐ | ⭐⭐⭐ | 用户态Hook | 多态+无文件+LOLBins | Lv3-Lv4 |
| **Avast/AVG** | ⭐⭐⭐ | ⭐⭐⭐ | CyberCapture云 | 签名窃取+延迟执行 | Lv3 |
| **腾讯管家** | ⭐⭐⭐(云) | ⭐(弱) | 几乎无本地Hook | 断网+签名窃取 | Lv2-Lv3 |
| **CrowdStrike** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 用户态Hook+云分析 | 间接syscall+栈欺骗 | Lv5-Lv6 |
| **SentinelOne** | ⭐⭐⭐⭐(AI) | ⭐⭐⭐⭐⭐ | 无户态Hook(内核Agent) | 多态编译+分散行为 | Lv5-Lv6 |
| **Cortex XDR** | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | 用户态Hook+WildFire | 间接syscall+LOLBins | Lv4-Lv5 |

### 速查：优先攻击哪个？

```
最容易绕过：  腾讯管家 >> 火绒 >> Avast >> McAfee
中等难度：    Defender >> ESET >> Bitdefender >> Cortex XDR
```
